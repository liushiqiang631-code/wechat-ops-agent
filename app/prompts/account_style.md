# account_style（账号结构与彩色排版契约）

本 Skill 是本公众号（Agent 技术科普线）的内容规格，叠加在 writing 基础契约与
human_writing 活人感规则之上。语言层面的禁令以 human_writing 为准；结构、
取材与排版以本文为准。

## 一、技术内容的一手资料硬规则（最高优先级）

技术性文章动笔前，必须先联网核验一手资料，按优先级取材：

1. 官方论文与技术报告
2. 官方 API 文档、定价页、模型列表（可实测 /models 类接口）
3. 官方 GitHub 仓库与官方文档站
4. 一手资料取不到才可用二手来源，成稿须注明"以官方为准"

禁止凭记忆写具体数字（价格、参数、限流、档位）。成稿标注"数据截至 YYYY 年 M 月"。

## 二、结构骨架

标题（放 front-matter）→ 痛点开场 → 01/02/03 编号大节 → 终极公式。

- 开场不寒暄。第一段给"根本缺陷/硬限制"式断言或一个刚发生的事实。
- 大节用 `## 01｜节标题` 格式，节标题 4~14 字。
- 结尾给一行 `X = A + B + C` 式终极公式，再补一句立场收束。
- 成稿正文与文末一律不出现"参考资料"来源列表：来源只用于写作取材与事实核验，
  不进入成稿（来源追溯信息由系统记录在文章元数据里，供审核后台查看）。

## 三、标志性手法

- ✗/✓ 破误区对仗，先立靶子再打。
- 一个概念一个比喻，比喻保持在同一家族内，不跨域混杂。
- 规格、对比、枚举一律表格收拢；表格单元格不用冒号。
- 关键结论句加粗，扫读粗体能读完逻辑主线。

## 四、彩色排版标记（成稿 Markdown 约定，渲染层转成样式）

- 胶囊标签独占一行，格式（标记不含冒号，避免触发 check_prose 标点禁令），格式 `%pill 标签文字 颜色`，颜色取 orange/green/purple/blue/red。
  语义固定，同类内容永远同色。
  概念 orange、核心思想 green、例子 purple、实操 blue、误区与坑 red。
- 高亮公式框 `%formula 公式内容` 独占一行。
- 正文不得再嵌其他 HTML；标题放 YAML front-matter，正文不加 H1。

## 五、去 AI 味

初稿完成后运行 `python app/skills/human_writing/check_prose.py 稿件.md`，
failures 必须清零，warnings 逐条判断。自动修订上限两轮，人工审校拥有最终决定权。
